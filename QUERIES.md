Skill 5 – Look Under the Hood

1. SQL generated by Sequelize

Endpoint: GET /members/1/loans

The following SQL query was generated by Sequelize when fetching a member and their loans, including book information.

SELECT
  "Member"."id",
  "Member"."name",
  "Member"."email",
  "loans"."id" AS "loans.id",
  "loans"."bookId" AS "loans.bookId",
  "loans"."memberId" AS "loans.memberId",
  "loans"."loanDate" AS "loans.loanDate",
  "loans"."returnDate" AS "loans.returnDate",
  "loans->book"."id" AS "loans.book.id",
  "loans->book"."title" AS "loans.book.title",
  "loans->book"."authorId" AS "loans.book.authorId",
  "loans->book"."publishedYear" AS "loans.book.publishedYear"
FROM "members" AS "Member"
LEFT OUTER JOIN "loans" AS "loans"
  ON "Member"."id" = "loans"."memberId"
LEFT OUTER JOIN "books" AS "loans->book"
  ON "loans"."bookId" = "loans->book"."id"
WHERE "Member"."id" = '1';

Sequelize uses LEFT OUTER JOIN to combine the members, loans and books tables. This allows us to retrieve the member and their loan history, including book details, in a single SQL query.


2. Equivalent raw SQL

```sql
SELECT
  m.id,
  m.name,
  m.email,
  l.id AS loan_id,
  l."loanDate",
  l."returnDate",
  b.id AS book_id,
  b.title,
  b."publishedYear"
FROM members AS m
LEFT JOIN loans AS l
  ON m.id = l."memberId"
LEFT JOIN books AS b
  ON l."bookId" = b.id
WHERE m.id = 1;

3. Comparison

Both queries return the same information about the member and their loans.

The Sequelize query is longer because it automatically selects more columns and uses aliases to organize the data into nested objects.

My raw SQL query is shorter and easier to read because I can choose exactly which columns I want to retrieve.

Sequelize makes it easier to work with relationships in JavaScript without writing SQL manually. However, raw SQL gives me more control over the query.

For this example, I think Sequelize is easier to use in the application, while raw SQL is easier to understand when looking directly at the database.
